# Security policy

## Supported versions

Until the first production release, security fixes target the default branch.
After launch, document the supported release window and backport policy here.

## Report a vulnerability

Do not open a public issue or include secrets, personal data, access tokens, or
exploit details in normal project channels.

Use GitHub private vulnerability reporting when enabled. Otherwise contact the
repository administrators through the organization's approved private security
channel. Include:

- affected commit/version and environment;
- impact and required privileges;
- minimal reproduction and request IDs with sensitive values removed;
- whether exploitation may be active; and
- a safe way to contact the reporter.

Do not access data you do not own, disrupt services, or perform load testing
without written authorization. Follow
[the security incident runbook](docs/runbooks/security.md) for internal
response.
